Background: Certificates on sovereignweb.site.

Short answer. moving-van.business already has its certificate (issued about 11:53 UTC; start time 10:53, backdated an hour). Only lee-elle-horowitz.artist is waiting. Do now: one Org apply by hand, scoped to Site__Artist__Lee-Elle-Horowitz with nudge_missing_certificates on, and nudge nothing else until it has its certificate. A slot is probably free now (about 1 to 2 by my estimate); if none is, the next is due by about 13:10 UTC and then one every 202 minutes. Then two IaC changes (below) so a new site never asks before its DNS exists and nudges go out one at a time in an order someone chose.

Measured at 12:27 UTC

  • New certificates since my last count (Cert Spotter): oscar.padel.sport and puter.platform (both issued about 03:03 UTC, as their sites were created), and moving-van.business (about 11:53 UTC). Nothing else.
  • All eight earlier sites and lee-elle-horowitz.artist resolve to sovereignwebsite.github.io and still serve GitHub's default *.github.io certificate.
  • The plan-only input (IaC work/factory.a-plan-only, 737cd3a) is not merged, so the exact certificate states are still unread.
  • The schedule's nudge (every sixth hour) re-saves only a missing or errored certificate. The eight are probably in state new, so the 06:17 and 12:17 UTC sweeps most likely spent nothing: the bucket has been refilling unused since 03:03.

Why moving-van got one and lee-elle did not

Both were created by the same Org apply run (45608263390). On the refill rate (one every 202 minutes from an empty bucket at about 03:03 UTC, when nvidia.platform was refused), about 2.6 certificates were free at 11:53, enough for both. So the limit alone does not explain lee-elle. The likely cause is a race: DNS apply and Org apply both start on the same push to requests/**. If Org apply sets the custom domain before Route 53 has the CNAME, GitHub's first attempt fails, the certificate stays in new, and GitHub does not retry by itself. This is likely, not proven: the plan-only report would show it.

What b.factory should change in the IaC

  1. Set a custom domain only once its DNS answers. In build/org-plan.mjs, plan pages.set_cname only when the domain's CNAME already resolves to sovereignwebsite.github.io (a DNS lookup in describe, through a public resolver). Otherwise add a note ("waiting for DNS") and let the next hourly run set it. No change to DNS apply is needed. This removes the race for every new site.
  2. Nudge one domain per run, in a chosen order.
    • A short ordered list, for example org/certificate-queue.json ({"first": ["Site__Artist__Lee-Elle-Horowitz", ...]}), kept by the maestros at Dinis's word. Repositories not on it come after, oldest request first.
    • The scheduled run nudges at most one domain per run: the first in that order whose certificate is missing, errored, or stuck in new or authorization_pending for more than 2 hours. Today a stuck new is never nudged by the schedule, and a missing one is nudged all at once.
    • Run the nudge hourly instead of every sixth hour. One nudge an hour is at most 24 a day, but a refused order costs nothing against the limit, and the bucket refills about 7 a day, so most hours either take the free slot or fail harmlessly.
    • A run by hand that names its repositories keeps today's behaviour (it re-saves whatever it is told to).
    Changes to .github/workflows/org-apply.yml (the schedule) need Dinis's merge.
  3. Merge the plan-only input (737cd3a) first, so the states can be read without spending a slot.

Not recommended

  • Re-saving all nine at once: at most one or two succeed and the order is down to chance.
